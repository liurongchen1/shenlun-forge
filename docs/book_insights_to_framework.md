# 经典书籍核心思想 → shenlun-forge 框架设计映射

> 从 Polya《怎样解题》、Kahneman《思考快与慢》、Manning《信息检索导论》中提取可直接指导框架升级的设计原则

---

## 一、Polya《怎样解题》(How to Solve It)

### 1.1 核心框架：四阶段解题法 → ACS 管线同构

Polya 将一切问题的解决归纳为四个阶段，这与 ACS 的四步管线惊人地同构：

| Polya 四阶段 | ACS 管线 | 核心动作 | 对应申论步骤 |
|---|---|---|---|
| **理解题目** (Understanding the Problem) | **Analyzer** (分析) | 识别未知量、已知数据、约束条件 | 审题（判断题型+看清要求） |
| **拟定方案** (Devising a Plan) | **Router + Retriever** (路由+检索) | 发现已知与未知的联系，寻找相关定理/方法 | 找要点（四步定位法） |
| **执行方案** (Carrying out the Plan) | **Processor** (加工) | 逐步执行，验证每步正确性 | 归类+逻辑组装 |
| **回顾反思** (Looking Back) | **Formatter + Quality Check** (格式化+质量检查) | 检验结果、尝试不同推导、寻找其他应用 | 按格式输出+三标准检验 |

**框架设计启示：**

> Polya 强调"理解题目"是第一步且最容易被跳过——很多学生拿到题目就急着算，不先搞清楚"未知量是什么、已知数据有哪些、约束条件是什么"。
>
> → **我们的 Analyzer 必须做"审题"，不能直接开干。** 这就是为什么 TaskProfile 要先于 Retriever。
>
> → 对应 P0 改动：TaskProfile 新增 `classification_dimension` 和 `output_logic` 字段，就是在"理解题目"阶段搞清楚"用什么维度分类"和"用什么逻辑组织"。

### 1.2 探索法词典关键条目 → 框架策略

Polya 的"探索法小词典"包含 67 个条目，以下是对框架最有启发的：

#### ① 辅助问题 (Auxiliary Problem)
> "如果你不能解决所提的问题，就先解决一个相关的问题。"
> 具体策略：
> - 能否想象一个更易access的相关问题？
> - 能否解决更一般的问题？更特殊的问题？一个类比的问题？
> - 能否只解决部分问题？

**→ 框架映射：降级策略的设计原则**

当主策略（如 LLM 精确分类）失败或代价过高时，自动降级到"辅助问题"：
- LLM 分类失败 → 降级到 embedding 相似度（更简单的问题）
- embedding 也不可用 → 降级到关键词匹配（更特殊的问题）
- 分类不了 → 至少按通用策略压缩（只解决部分问题）

→ **这正是我们的三级降级分类器：关键词 → embedding → LLM**

#### ② 分解与重组 (Decomposing and Recombining)
> "将条件的不同部分分开"——把问题拆成若干独立约束条件，每个条件分别产生一个"轨迹"（locus），最终解是各轨迹的交集。

**→ 框架映射：多信号融合评分**

Retriever 对每个文本块打分时，不应只用一个综合分数，而应分解为多个独立信号：
- 位置信号（首尾加权）→ 一个轨迹
- 词频信号（高频词密度）→ 一个轨迹
- 结构信号（标题/编号/关键词）→ 一个轨迹
- 来源权威信号 → 一个轨迹

最终相关性 = 各信号的加权组合（交集）。

→ **对应 P2-P5 改动：Retriever 新增 4 个评分因子**

#### ③ 倒着干 (Working Backwards)
> "从目标出发，倒推需要的前置条件。"

**→ 框架映射：输出驱动的压缩策略选择**

不是先压缩再想怎么用，而是先看"输出要什么格式"→ 倒推"需要哪些信息"→ 再决定"怎么压缩"。

→ 这就是 P9 改动：Formatter 根据 `output_logic`（并列/因果/递进）反向决定 Processor 的组装方式和 Retriever 的提取重点。

#### ④ 归纳法 (Induction)
> "通过观察特殊实例发现一般规律。"

**→ 框架映射：从实例中学习分类模式**

Analyzer 可以从 query 的关键词中"归纳"出分类维度：
- 多次出现"主体"+"责任"→ 归纳出"主体分类"维度
- 多次出现"原因"+"结果"→ 归纳出"因果链"维度
- 多次出现"优点"+"缺点"→ 归纳出"正反对比"维度

→ **对应 P1 改动：Analyzer 信号二（query 关键词 → 分类维度推断）**

#### ⑤ 观察未知量 (Look at the Unknown)
> "观察未知量！试着想一个有相同或类似未知量的熟悉问题。"

**→ 框架映射：从 query 意图反推压缩策略**

不要从"文本有什么"出发选择压缩策略，而要从"用户想要什么"出发：
- 用户要"概括论点" → 需要保留论证结构 → 选论证压缩策略
- 用户要"提取事实" → 需要保留数据细节 → 选事实提取策略
- 用户要"对比分析" → 需要保留对比维度 → 选对比结构策略

→ **这是框架从"文本驱动"转向"意图驱动"的核心转变**

### 1.3 Polya 的设计哲学总结

| 原则 | 框架体现 |
|---|---|
| 先理解再动手 | Analyzer 先做任务分析，再进入管线 |
| 大问题拆成小问题 | 多级评分因子分解、多项目隔离 |
| 辅助问题策略 | 三级降级分类器 |
| 倒着干 | 输出格式驱动压缩策略 |
| 归纳法 | 从 query 关键词归纳分类维度 |
| 回顾反思 | Formatter 质量检查（三标准验证） |

## 二、Kahneman《思考，快与慢》(Thinking, Fast and Slow)

### 2.1 双系统理论 → 三级降级分类器

Kahneman 的核心发现：人类有两种思维模式——

| 特征 | 系统1（快思考） | 系统2（慢思考） |
|---|---|---|
| 速度 | 自动、快速 | 缓慢、费力 |
| 能耗 | 几乎不费力 | 消耗大量脑力 |
| 控制 | 无意识、自动运行 | 有意识、主动控制 |
| 准确度 | 容易出错但有统计效率 | 准确但懒惰 |
| 关系 | 默认主导 | 只在系统1搞不定时介入 |

**→ 框架映射：三级降级分类器的认知科学基础**

```
System 1 快速层:  关键词规则匹配    ← 0ms，零成本，覆盖 60% 场景
  ↓ 不够确定时
System 1.5 中间层: embedding 相似度  ← ~50ms，低成本，覆盖 25% 场景
  ↓ 仍然不确定时
System 2 深度层:  LLM 语义分类       ← ~2s，高成本，覆盖 15% 场景
```

这不是工程妥协，而是**对人类认知架构的模拟**。Kahneman 证明，系统1的"快速但可能出错"+ 系统2的"慢但准确"组合，是自然界最优的信息处理策略。

→ **这给框架的设计哲学提供了认知科学背书**

### 2.2 关键认知偏差 → 框架设计警示

#### ① 替代启发式 (Substitution Heuristic)
> "面对复杂问题时，系统1会自动替换为一个更简单的问题来回答，且自身无法察觉。"

**→ 框架启示：警惕"看起来相关但不是"的陷阱**

Retriever 打分时，一个文本块"看起来重要"（比如很长、有很多数字）不代表它"对当前任务真正重要"。
- 解决方案：引入 TaskProfile 作为"锚"，所有评分都必须相对于任务目标，而非绝对特征。

→ **对应 P1 改动：TaskProfile 驱动 Retriever 评分**

#### ② 锚定效应 (Anchoring Effect)
> "人在不确定情况下做判断时，会被最先接触的信息（锚点）影响，即使这个信息完全无关。"

**→ 框架启示：文本位置的信息价值偏差**

- 文章开头和结尾往往包含最重要的信息（"锚点"位置）
- 但中间段落也可能包含关键论证
- 解决方案：首尾加权但不过度加权（位置信号是多个因子之一，不是唯一因子）

→ **对应 P2 改动：Retriever 首尾位置加权，但权重可控**

#### ③ 可得性启发 (Availability Heuristic)
> "判断事件频率时，人会根据'想起来有多容易'来判断，而不是看实际统计数据。"

**→ 框架启示：词频≠重要性，但词频是重要性的有效代理**

- 某个概念在文本中反复出现 → 说明它大概率是核心话题
- 但仅靠词频不够（就像人仅靠"想得起来"判断会出错）
- 解决方案：词频作为一个评分因子，但不是唯一因子

→ **对应 P3 改动：Retriever 词频特征加权**

#### ④ 代表性启发 (Representativeness Heuristic)
> "根据某事物与某类别的'相似度'来判断其归属，忽略基础概率。"

**→ 框架启示：分类时不能只看"像不像"，还要看"是不是"**

- 一段文本"看起来像"技术类，但如果用户问的是"社会影响"，它可能不应该被高优保留
- 解决方案：分类决策必须同时考虑"文本特征"和"任务需求"

→ **对应 P10 改动：Formatter 分类维度分组——分类维度由任务决定，不由文本特征决定**

#### ⑤ 规划谬误 (Planning Fallacy)
> "人们倾向于过度乐观地估计完成时间，只关注最佳情况，忽略历史数据。"

**→ 框架启示：压缩率预估需要外部视角**

- 不能只看"理论上能压缩多少"，要看"在类似文本上实际压缩了多少"
- 解决方案：引入历史压缩率统计作为预估锚点

→ **可选改进：Compressor 记录历史压缩统计，用于预估和策略调整**

### 2.3 Kahneman 的设计哲学总结

| 原则 | 框架体现 |
|---|---|
| 快慢系统协作 | 三级降级分类器（快→中→慢） |
| 系统2是懒惰的 | 只在系统1不确定时才启动高成本分析 |
| 替代启发式陷阱 | TaskProfile 约束评分，防止"看起来重要≠真正重要" |
| 锚定效应 | 首尾位置加权（但不过度） |
| 可得性偏差 | 词频作为代理信号（但不是唯一信号） |
| 代表性偏差 | 分类由任务驱动，不由文本特征驱动 |
| 规划谬误 | 历史统计辅助策略选择 |

## 三、Manning《信息检索导论》(Introduction to Information Retrieval)

### 3.1 核心概念 → Retriever 理论基础

#### ① TF-IDF（词频-逆文档频率）
> 一个词在当前文档中出现频率高（TF高），但在整个语料中少见（IDF高），则这个词对当前文档的"区分度"贡献最大。

**→ 框架映射：Retriever 评分的核心公式基础**

```
score(segment, query) = Σ tfidf(term, segment) × query_boost(term)
```

- tf(term, segment)：词在当前文本块中的频率 → 局部重要性
- idf(term)：词在整个文档中的稀有度 → 全局区分度
- query_boost(term)：词在 query 中的权重 → 任务相关性

→ **对应 P3 改动：Retriever 引入 TF-IDF 式加权**

#### ② 布尔检索 + 向量空间模型
> 布尔模型：精确匹配，非黑即白。向量空间模型：模糊匹配，用余弦相似度衡量相关性。

**→ 框架映射：两级检索策略**

- 第一级（粗筛）：关键词布尔匹配 → 快速过滤明显不相关的文本块
- 第二级（精排）：向量相似度排序 → 在候选集中精确打分

→ **与三级降级分类器呼应：粗筛→精排**

#### ③ 文本分类与聚类
> 第13章"Text Classification and Naive Bayes"、第14章"Vector Space Classification"、第16-17章"Clustering"

**→ 框架映射：Router 的分类理论基础**

- 朴素贝叶斯分类器 → 关键词规则的数学基础
- 向量空间分类 → embedding 相似度的理论基础
- 层次聚类 → 多项目隔离的聚类思路

→ **对应 P12 改动：v0.3 Router 的分类策略库**

#### ④ 相关性反馈 (Relevance Feedback)
> "用户第一次搜索的结果可以反馈给系统，用于改进后续查询。"

**→ 框架映射：压缩质量反馈机制（远期设想）**

如果压缩结果在下游 LLM 任务中表现不好（比如回答不准确），可以反馈给 Retriever 调整评分权重。

→ **远期可选改进：引入任务结果反馈回路**

### 3.2 Manning 的设计哲学总结

| 原则 | 框架体现 |
|---|---|
| TF-IDF 平衡局部与全局 | Retriever 多因子加权评分 |
| 粗筛+精排两阶段 | 关键词过滤 → 向量精排 |
| 分类与聚类理论 | Router 分类策略库 |
| 相关性反馈 | 远期：任务结果反馈调整评分 |

## 四、跨书共识：三个理论体系共同指向的设计原则

| 共识原则 | Polya | Kahneman | Manning | 框架体现 |
|---|---|---|---|---|
| **先分析再行动** | 理解题目是第一阶段 | 系统2监控系统1 | 查询解析先于检索 | Analyzer 先行 |
| **多信号融合** | 分解条件为多个轨迹 | 避免单一启发式 | TF-IDF多因子 | Retriever 多因子评分 |
| **降级策略** | 辅助问题法 | 快慢系统协作 | 粗筛+精排 | 三级降级分类器 |
| **输出驱动** | 倒着干 | 参照点决定判断 | 相关性由查询定义 | output_logic 反向驱动压缩 |
| **回顾验证** | 第四阶段：回顾 | 系统2纠错 | 评估指标 P/R | Formatter 质量检查 |
| **从实例学习** | 归纳法 | 经验启发 | 训练集→模型 | query关键词→分类维度 |

## 五、对 v0.3 升级的直接指导意义

### 5.1 框架设计哲学的学术定位

在论文或推广文中，可以这样描述框架的设计哲学：

> "shenlun-forge 的设计深受三个经典理论体系的启发：
> 1. Polya 的启发式问题解决方法论——将文本压缩视为'解题'过程，遵循'理解→规划→执行→回顾'四阶段；
> 2. Kahneman 的双系统认知理论——用快慢系统协作的架构实现高效准确的语义分类；
> 3. Manning 的信息检索理论——用 TF-IDF、向量空间模型等经典方法实现精准的文本检索与评分。
>
> 这三个理论的共同指向是：**先理解问题，再多维度分析，最后输出并验证**——这恰好也是申论写作的方法论。"

### 5.2 改动项优先级与理论支撑

| 改动项 | 理论支撑 | 优先级 |
|---|---|---|
| P0: TaskProfile 新字段 | Polya"理解题目" + Kahneman"参照点" | 🔴 最高 |
| P1: Analyzer 信号二 | Polya"归纳法" + "观察未知量" | 🔴 最高 |
| P2-P5: Retriever 多因子 | Polya"分解重组" + Kahneman"多启发式" + Manning"TF-IDF" | 🟡 高 |
| P6-P8: Processor 改进 | Polya"执行方案" + "归纳组装" | 🟢 中 |
| P9-P11: Formatter 改进 | Polya"倒着干" + "回顾反思" | 🟢 中 |
| P12: Router 分类策略库 | Manning"文本分类" + Kahneman"双系统" | 🔵 远期 |

### 5.3 新增：框架的"六条设计公理"

基于三本书的共识，提炼出框架的六条设计公理：

1. **理解优先公理**：任何处理之前，必须先"审题"——明确任务类型、分类维度、输出格式。（Polya）
2. **多因子融合公理**：不做单一维度判断，任何评分/分类决策都融合多个独立信号。（Polya + Manning）
3. **降级优先公理**：高成本方案失败时，必须有低成本替代方案可用。（Kahneman + Polya）
4. **输出驱动公理**：压缩策略由输出需求决定，不由输入特征决定。（Polya"倒着干"）
5. **验证闭环公理**：每个阶段的输出都应该可验证、可回溯。（Polya"回顾"）
6. **统计锚定公理**：利用历史统计数据辅助决策，避免"规划谬误"。（Kahneman）
