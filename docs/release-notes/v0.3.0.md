## 升级前必读 / Read before upgrading

**默认策略变了。** `ShenlunForge.create()` 和命令行的默认策略从 `acs` 改成了 `simple`。
如果你原来直接写 `ShenlunForge.create()` 不带参数，升级后行为会变：**不再调用 LLM**，
输出更短、更快、零成本。想保持原行为，请显式传 `strategy="acs"`。

**The default strategy changed** from `acs` to `simple`. A bare
`ShenlunForge.create()` now skips the LLM entirely. Pass `strategy="acs"` to keep the
previous behaviour.

---

## 不改代码就能得到的好处 / What you get for free

- **不会再越压越长**。压不动的时候原样返回，并置 `stats["passthrough"] = True`。
- **本来就装得下的历史不再被压缩**——那只会丢信息，省不下任何东西。
- **超长历史不再吃掉几个 GB 内存**（embedding 路径的批大小以前是 256）。
- **`shenlun-forge version` 显示的版本号是对的**（以前硬编码成 0.2.0，而实际是 0.2.4.1）。
- **结构化输出的长度不再超出预算 9 倍**，hcs 也不会因为按字符估算而撑破预算。
- **LLM 没配好时会明确告诉你**，不再静默换成规则模式还照常返回结果。

- Compression no longer returns a result longer than its input.
- Context that already fits the window is left untouched.
- Long histories no longer consume gigabytes of memory.
- `shenlun-forge version` reports the real version.
- Degraded runs are reported instead of silently falling back.

## 两个实测结论，会影响你怎么配 / Two findings that change how you configure it

这一版做了六轮评测，有两个结论值得你在升级后照着调整：

**1. 换检索器的影响，超过所有调参。** 在"答案埋在长历史早期"的数据上，语义检索比
截断高 **25 个百分点**（统计显著）；而在普通工作对话上两者**打平**——因为答案就在
末尾，保留尾部本已最优。所以：**长历史里要找回早前说过的信息 → 用
`retriever_type="embedding"`**；其他情况 `simple` 就够，它免费且毫秒级。

**2. `hcs` 不再推荐。** 在包含 2.6 万条命令执行的中文会话上，它与免费方案打成平手
（45.9% vs 46.0%），却要多一次 LLM 调用。六次评测里它从未显著更好。代码保留，推荐取消。

**Retriever choice dominates every tuning knob** (+25 points on data where the answer
is buried early; a tie on ordinary work conversations), and **`hcs` is no longer
recommended** — it never beat the free options while costing an extra LLM call.

数据、方法和可复现的评测工具都在仓库的 `benchmarks/` 下。
Numbers, method and reproducible tooling live in `benchmarks/`.
