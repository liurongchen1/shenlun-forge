## 这个版本改了什么 / What changed

两件新增，都跟同一件事有关：**让模型知道自己手里有多少材料。**

**1. 摘要会自己交代缺口。** 每条压缩结果末尾多一行：

```
【压缩说明】另有 37 条较早历史未包含在上文（约 12,480 tokens）。如果这里找不到答案，请说明缺口，不要臆测。
```

模型不知道压缩器丢过东西，所以它分不清"没有"和"我没看到"。默认开启，语言跟随提问，
token 从 `max_tokens` 里预留（不会偷偷撑破预算）。关掉用 `dropped_notice=False`，
命令行 `--no-dropped-notice`；无论开关，`stats["dropped_messages"]` 与
`stats["dropped_tokens"]` 都照常上报。

实测（同批点开/关对照、配对比较、按对话聚类）：

| 数据 | 开 | 关 | |
|---|---|---|---|
| LongMemEval，96 条独立长历史（压到 4%） | 11.5% | 12.5% | 打平（p=0.32） |
| 真实工作对话，131 点 / 12 个对话 | 46.3% | 40.9% | +5.4pp；保留 20–50% 那一档 **+10.4pp**（p=0.034） |
| 聊天记录，163 点 / 29 个对话 | 40.7% | 36.7% | +4.1pp（p=0.026）；同一档 **+11.6pp**（p=0.005） |

**它没有做到我原本以为的事。** 我加它的动机是防幻觉，实测没测出来——开与关两种情况
下"答了但没答到要点"的比例都在 0%–3%，模型也没有更常说"缺失"。动的是分数，机制没
测出来，所以文档里凡是"防止编造"这类说法都改掉了。

**2. `shenlun-forge demo`：一条命令，不用 key、不联网、不到一秒。**

```bash
shenlun-forge demo          # 中文加 --lang zh
```

内置一段 32 条消息、三个互不相关话题的对话，交给「粗暴截断」和本库各跑一遍，然后打印
**各自留下了哪几条消息**、能回答问题的那条有没有活下来。演示刻意不展示"文本变短了"——
截断也变短而且免费；差别在**留下的集合跟不跟着问题走**。两个测试盯着这个对照的真实性：
一个断言答案真的活下来，一个断言截断真的丢掉它。

---

**Two additions: the summary now names what it left out** (on by default, in the
language of the question, reserved inside `max_tokens`, off with
`dropped_notice=False`), **and `shenlun-forge demo`**, which runs a built-in
conversation through plain truncation and through this library and prints which
messages each one kept. The measured effect of the note: nothing where the
history is cut to 4% of its size, +4 to +5 points overall on two private
datasets, and +10 to +12 points where 20–50% of the history survives. A
backward-compatible release.
